# Operation, updates and recovery

This is a local Mac/iPhone service, not an unattended cloud telephone provider. Codex, its managed message relay, the Mac, and iPhone call continuity must remain available. No claim of availability while the Mac sleeps or Codex is closed is warranted.

## Inspect without calling

Run `python3 scripts/call_the_boss.py status` for the exact current task and recent service states, and `doctor` for live relay/daemon readiness and version diagnostics. Neither verifies audible speech, cellular delivery, Realtime quota, or execution of a phone command.

States describe queued, preparing, dialing, connected, delivered, processing, call-completed, failed, skipped, and needs-review stages. `completion_scope=phone_call_only` means a completed telephone session, not a completed source task. A skipped report is not a completed call. Real source-task completion still requires source-turn evidence.

Failures are stored under the private state directory's `service-status/`. When `phone_failure_notifications` is enabled, an incident submits at most one macOS desktop notification. It never sends a message to a Codex task or triggers a new call. `submitted_to_os` is not evidence the banner appeared: macOS notification settings or Focus may hide it. If a failure remains unseen, inspect the durable status and guide the user to verify notification permissions; do not pretend a notification test passed visibly.

Native opening failures additionally link a per-root `preparations/` manifest to that exact root's rejected clips. Do not infer network loss, a local audio fault, or a cloud fault from ASR mismatch alone. Keep the rejected evidence and the unchanged acceptance gate.

Private conversations now have one readable `.md` per call and a stable `conversations/<exact-source>/电话记录.md` view containing the latest dialogue and up to 100 historical links. Display writes occur only at archive checkpoints, not audio/word callbacks. Input snapshots update their original call, never create extra calls; older snapshots cannot overwrite a settled view. A derived-display failure is recorded separately and must not fail or resend a call/command. The text is recognition/playback evidence, not a verified verbatim handset recording or proof of task completion. Files remain private mode 600 and outside the share ZIP. Opening a panel is separate from updating the file, and a queued `open_in_codex` result is not proof it is visible.

For missing visible history, first verify the raw exact-source archives. Backfill only derived views with the installed runtime's `phone_transcript.py --archive-dir /absolute/private/conversations/<exact-source> --source-thread-id <exact-source>` (using that runtime's Python). It neither modifies original JSON nor sends messages or dials. Check the exported count and errors; open/link the resulting absolute file in the current task. Do not repair the live Codex database or inject old commands to reconstruct chat bubbles.

A specifically identified paginated-history projection error can prevent the exact source task from forking at all. Label `context_binding=ephemeral_snapshot_of_source`; never call it a complete-history fork or claim the underlying Codex store was repaired. Missing/mismatched metadata, unavailable context, other RPC errors, timeouts and authentication failures remain failures before dialing. Never repair the database, replay old source tasks or route execution into the voice view. This recovery stays inside the original preparation deadline.

Automatic fallback summaries must bind both the exact temporary context and the accepted summary turn. Buffer only a bounded set of early completion events until the turn/start response supplies its identity; reject absent/conflicting identities, malformed structured output and overflow. Another turn's completion cannot finish this summary. Request acceptance and final output share one original deadline, and a closed connection wakes the wait immediately. ## Queued-report review

Automatic reports older than 15 minutes are held with `needs_review / queue_age`, not deleted or automatically dialed later. Missing, invalid, or future-dated creation metadata also requires review. The limit is the local `phone_queue_max_age_seconds` setting; explain its effect before changing it. Newer valid reports are not blocked behind held reports.

Only when the user explicitly asks to release one identified held report, run:

```bash
python3 scripts/call_the_boss.py confirm-queued-report --job-id EXACT_JOB_ID --confirm
```

The command checks the current subscribed source, refuses active/unconfirmed lines, retains original creation time and audit history, and records explicit confirmation. It consumes the current root's completion-call allowance, so no second completion call may be requested. A failed/uncertain phone attempt cannot be reopened through this command; it accepts only jobs still in the held queue. Do not release every held report at once or delete queue files to bypass deduplication. Disabling a source task prevents its queued reports from dialing without deleting history.

## Update safely

For a manual call test, finish the originating root turn promptly after observing the dial state; do not occupy it with a long wait for the caller's next command. An active source may receive a relayed command only at its next model boundary. A manual call still consumes this root turn's one-call allowance. Its required `--report` must describe the actual current result; a cached opening is not permission to reuse an obsolete status, and missing copy must fail before dialing.

1. Inspect status, the queue, and real line state. With no active, queued, or unconfirmed call, run `python3 scripts/call_the_boss.py stop-for-update`. This temporarily stops the daemon, not the task subscription. Do not end the update turn in this intermediate state.
2. Following the user's installation/dependency-download authorization, run `python3 scripts/call_the_boss.py install --yes`. It locks installation and runtime startup, refuses an active daemon, tests a candidate in its permanent version path, then switches the stable link. Failure preserves the previous runtime. Keep failed candidates and old versions; do not batch-delete them.

Graceful relay shutdown has a bounded client-drain period; a lost reply during shutdown is uncertain delivery, never permission to resend. A missing process/command session without an exit record remains an unexplained lifecycle failure, not proof that these startup/shutdown fixes prevent future exits.
4. For an already configured phone loop, refresh and trust its existing completion hook from the newly activated runtime with `.venv/bin/python phone_agent.py install` in that runtime directory. If the update fails, report it and restore/verify the preserved version before claiming recovery.

It does not dial, change the voice, or enable another task. New installations and other tasks stay off.
