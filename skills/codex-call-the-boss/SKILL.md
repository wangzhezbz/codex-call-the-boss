# Call the Boss

This skill controls a persistent phone bridge, but activation is scoped to one exact Codex thread. Installing or explaining the skill never authorizes a call. An explicit request such as “为当前会话启用” authorizes subscription; an explicit “测试打给我” authorizes one immediate test call.

## Required behavior

Once the current thread is enabled:

1. Every completed root turn queues exactly one new call attempt for that turn while the exact session remains enabled. This includes repair, explanation, and failed-call follow-up turns. Deduplicate by turn ID, not by topic or by the previous call's outcome.
2. After all work and verification, immediately before ending that root turn, write a separate phone-only status sentence based on the actual outcome and stage it invisibly with `python3 scripts/call_the_boss.py stage-report --text "<phone-only status>"`. If the user explicitly says not to call for this completion, keep the session enabled and instead make `python3 scripts/call_the_boss.py skip-call` the final tool command. That one-turn skip is consumed into a persistent completion record so the Stop hook and rollout watcher cannot call later. Do not reuse or slice the visible final response, and never put control comments, markers, or phone metadata in the visible reply.
3. The phone-only status is 12–36 Chinese characters when practical, conversational, and one complete sentence. Write it from this task's actual latest outcome before looking up audio. Never choose an old status sentence merely because its recording is already cached, including for a manual retry; a matching cache may reuse the audio only after the current copy is chosen. State only the useful outcome. Exclude Markdown, paths, URLs, test counts, implementation details, English identifiers, invitations, and filler. Do not include “老板”; the runtime adds it. If blocked, state the blocker and the one decision needed instead of claiming completion.
4. After pickup, use local phone-audio speech detection to notice the caller's opening “喂” without waiting for Realtime transcription. Then say only: “老板，<phone-only status>.” If the greeting cannot be detected, use a short pickup timeout; never leave six seconds of dead air.
5. Keep the opening completion report and command-delivery receipts brief; ordinary conversation stays warm and complete, usually one to three Chinese sentences and longer when needed. Recognition and answers come from the logged-in Codex account. Preserve the selected renderer. The local default is the user's macOS voice; explicitly selected `realtime-unified` uses the same native voice for the opening, conversation, command receipts, and failure notices. Reuse the approved opening's speech-style guidance for live speech and its backing responses; do not introduce a second personality. A matching voice ID or prompt is not proof of identical audible delivery. Native mode validates and caches notices before dialing, then streams answers; it must not silently fall back to a different system voice. Do not add paid services unless the user explicitly requests and authorizes that provider; optional Doubao TTS setup is in [references/doubao.md](references/doubao.md).
6. Assemble complete acoustic utterances and classify every nontrivial utterance with structured output from the existing logged-in Codex in an isolated read-only context, in parallel with answer generation. Hold answer/acknowledgement audio until classification; never dispatch from spoken wording or a delegation event. New unresolved speech holds unsent commands so a pending cancellation can be classified first. Already-sent commands cannot be acknowledged as undone. Send original words plus quoted history and a unique command marker to the exact subscribed source thread. Say it started only when that exact marker is observed in the target turn's user record or validated fixed-relay phone-message envelope, not merely when any new turn appears. Reconcile confirmed final speech at hangup; archive incomplete fragments without executing them. Never repeat an uncertain send.
7. The source thread actually performs the task. Its completion queues the next one-call report, including when it completes while the previous call is still open.
8. Farewells during an established phone call stay silent. A failed dial is terminal only for that single queued job: never retry or click twice inside that job. It must not suppress the next distinct root turn's one call attempt; the next completed turn calls normally without requiring the user to say "重试".

Never substitute a new task, a detached voice chat, or a local language model for the subscribed source thread. Never subscribe every Codex thread globally.

## Route the request

- Before asking permission for the first test call, teach the caller how to use it: answer with “喂”, listen to the short report, ask follow-up questions or discuss alternatives naturally, then introduce an execution request with “下一步的任务是：XXXXX”. Give examples of a status question, explanation/comparison and one concrete task with an acceptance condition. Explain that a question or hypothetical discussion is not itself an instruction to change the project. Wait for the factual command receipt; after confirmed delivery they may hang up and await the next completion call. If execution is unconfirmed, direct them to the original task without claiming it started. Explain the one-action-per-call limit and that submitted-task changes/cancellations belong in the original task. This phrase is a recommended clear convention, not a new password, keyword-only classifier, or authority override. Preserve structured intent classification and existing permissions.
- During onboarding, ask the user directly for the receiving phone number (different from the outgoing line). They may supply it in this private conversation; do not echo it in summaries, logs or public files. Pass it to configuration through private interactive input, never shell arguments or a shared file. API keys remain hidden-terminal input only. If this is a simulation, accept a fictional number and do not save configuration, synthesize paid audio or dial.

- For a first-time user or shared archive, do not assume an existing installation, phone number, voice configuration or enabled task. Start with [references/setup.md](references/setup.md); the user-facing Chinese walkthrough is [references/quick-start-zh.md](references/quick-start-zh.md). Guide prerequisite checks, approved installation, private configuration and a separately requested test call. Only reuse an installation after checking that it exists and is healthy. Never copy another owner's private state. Sharing/importing alone does not authorize subscription or calls.
- During first-time setup, ask the owner to choose system speech or Doubao speech before voice configuration. Explain that system speech has no additional TTS-provider fee, while Doubao sends synthesis text to Volcengine and may be billed. Wait for the choice; a missing answer is not consent or a default selection. If Doubao is chosen, read [references/doubao.md](references/doubao.md), present its official console links in order, let the owner choose a supported model and exact voice ID, then guide private API-key entry and an approved no-dial sample. Do not reuse the maintainer's profile for new users or change an existing owner's selection without asking.
- For first-time setup of this public package, use the documented [synchronous Stop route](references/synchronous-stop.md) after the user approves configuration. Check host compatibility and stop if the required hook is unavailable; do not fall back to private IPC. Preserve an existing installation's transport unless the user authorizes migration. The fixed relay identity, `start-relay`, asynchronous watcher and direct-dial instructions below apply only to the legacy desktop-relay mode, not to synchronous Stop.
- If the user asks to enable reports but wait for confirmation before testing, honor the no-call request for the setup completion with `skip-call` as the final phone operation. Explain that later enabled task completions call automatically. Never treat installation or an unconfirmed test as call authorization.
- Routine question-wait filler is off by default (`phone_query_wait_notice_enabled` absent or false). Do not turn it on merely because an older diagnostic paragraph describes a waiting notice. Preserve real timeout/failure feedback and the original deadlines.
- First inspect the selected `phone_command_transport`. When it is `synchronous_stop`, read [references/synchronous-stop.md](references/synchronous-stop.md) and follow that route instead of the legacy private-relay startup, async watcher and immediate manual-dial instructions below. It retains exact-session subscription and one-attempt rules but uses a real synchronous Stop waiting window. Never manufacture that window from an ordinary command, retry a rejected private entry, or claim a staged test has already dialed.

- For an explicitly requested Doubao voice renderer, read [references/doubao.md](references/doubao.md). It changes speech synthesis only, not caller recognition, the source task, action authorization, or one-call-per-turn rules. Never infer permission from a native voice failure.
- If the current session is not enabled, explanation, inspection, or packaging remains read-only and does not subscribe or call. If the exact session is already enabled, every completed root turn follows the one-call rule above.
- For first-time setup or repair, read [references/setup.md](references/setup.md) completely and follow it.
- For updates, failures, queued-report recovery, or diagnostic export, also read [references/operations.md](references/operations.md). Installation now requires Python 3.11+, a stopped idle daemon, and transactional candidate validation; never restore the old in-place overwrite installer.
- If the owner explicitly accepts a particular opening address and asks to keep it, follow the fixed-address selection in [operations](references/operations.md). Preserve those exact samples, not merely the generation prompt; the status report remains dynamic. A slightly better sample is not acceptance.
- For an explicitly chosen fixed-address/body strategy, follow the mode comparison and idle `set-opening-mode` procedure in [operations](references/operations.md). Default full-source behavior stays unchanged until the owner chooses; automated QA does not establish naturalness of the independent body.
- For an explicit enable request, run `scripts/call_the_boss.py plan`, resolve setup problems, then run `scripts/call_the_boss.py enable`. The current `CODEX_THREAD_ID`, the fixed relay identity, and the Codex desktop message relay must all be available.
- For an explicit disable request, run `scripts/call_the_boss.py disable`. Disabling one thread must not affect other subscribed threads.
- For status, run `scripts/call_the_boss.py status` and `scripts/call_the_boss.py doctor`.
- Before staging the final report, verify the live message relay. If it is down, restart `start-relay` in a managed Codex command session, keep that session alive, and verify again. A stale socket or an old green status file is not readiness. `stage-report` now checks both the live relay and daemon. If ordinary staging was omitted, the runtime asks logged-in Codex for a separate short spoken summary before dialing; this slower fallback must not say “看屏幕” or read the final reply verbatim.
- For a Codex conversational voice, run `scripts/call_the_boss.py list-realtime-voices`, then run the no-dial `scripts/call_the_boss.py voice-self-test --voice "..." --output "/absolute/path/realtime-check.wav"`. Switch with `set-realtime-voice` only after testing saved audio, long replies and interruptions. Then explicitly initialize its private notice library with `scripts/call_the_boss.py prepare-voice`. This reports bounded per-clip progress without dialing. Ordinary `stage-report` and `test-call` require that library and prepare only their dedicated opening. Missing/rejected audio stops before queuing; do not lower the gate, switch voice, or silently rebuild the whole library during a call attempt.
- For a local opening/fallback voice change, run `scripts/call_the_boss.py list-phone-voices`, map the user's chosen sample to its exact installed identifier, then run `scripts/call_the_boss.py set-phone-voice --identifier "..."`. This deliberately switches all speech back to the local renderer. It preserves rate and pitch and never authorizes an extra test call.
- For packet-loss diagnosis, compare direct media with the user's already configured loopback SOCKS proxy only if one exists. `set-media-route --route system-socks` affects this phone bridge only; `--route direct` restores its direct media. Never install a proxy or change global network settings implicitly. Verify without dialing; a handshake or one good sample is not complete conversation acceptance.
- For an explicitly requested no-call completion, do not disable the session. After all verification, run `scripts/call_the_boss.py skip-call` once as the last tool command before the visible final reply.
- For an explicitly requested test call, write a truthful 12–36 character task-specific opening and run `scripts/call_the_boss.py test-call --confirm --report "<actual short status>"` once. Never use “结果在当前窗口” or another instruction to read the screen as the report. Do not retry if it fails or is unanswered.
- A manual test already uses that root turn's one call. Do not request another completion call afterward; its persistent one-turn guard must survive final-report staging. Later distinct task completions still call normally.

## Safety invariants

- Resolve and record the exact source thread ID before enabling or dialing. If it is unavailable, stop.
- The global Stop hook may observe all turns but may queue only IDs present and enabled in the session registry.
- Keep exactly one phone Stop hook. Before queuing, it must confirm that the background daemon was spawned from the active Codex process and passed a real Accessibility probe. Never run the iPhone dialer from a LaunchAgent: macOS gives that process a different TCC identity even when Codex itself is authorized.
- A Codex desktop backend that was already running before installation may not load the new Stop hook into an existing thread. Keep the daemon's exact-session rollout watcher enabled as a fallback: begin at EOF, react only to later root `task_complete` records, never backfill, and serialize persistent turn-ID deduplication across queue, calling, done, and failed records. The Stop hook and watcher must still produce only one call attempt together.
- Hold one state-directory daemon-instance lock for the worker's full lifetime so source, installed, or upgraded runtime copies cannot compete for the same call queue.
- Prepare the dedicated phone copy and cached notices before queuing. Before dialing, finish the bounded Realtime startup and verify both the live media connection and event channel; recheck immediately before the single confirmation click. Slow or failed startup must stop before dialing, never consume an answered phone call or be reported as a mid-call disconnect. Once CallServices reports `Active`, accept caller audio and start the local greeting clock immediately. Do not precompile the Siri voice helper; keep it under Apple's signed Swift host. The Accessibility helper alone may be precompiled.
- On the Codex v3 audio path, never restore RTP timestamp discontinuities as silence and never count leading zero PCM as speech. Compact the decoded waveform, start only after a completed sentence has a safe audio lead, and release a short remaining turn at `turn.done`. Unified native mode uses a prepared same-voice notice for a silent/truncated turn or connection failure, never macOS speech. A self-test passes only after an assistant `turn.done` plus a non-silent 48kHz waveform, not merely because one audio callback fired.
- Treat intelligibility as an acceptance gate, not a root-cause diagnosis. Failed transcription or a short decoded waveform alone does not prove a cloud generation fault. Compare received Opus before the jitter buffer, independent decode, local rendering, and hardware loopback before assigning blame; keep the selected local output while native output remains unverified.
- A queued automatic call must carry `session_subscription=true`; the daemon rechecks the registry before dialing.
- Return an accepted phone command through the restricted Codex desktop `send_message_to_thread` relay, using the fixed relay identity as caller and the exact subscribed source thread as target. The relay identity transports messages only; it must never answer or execute the task itself. Never use `codex exec resume` for an app-owned source thread because the desktop app already holds its active writer.
- Refuse to dial when the fixed relay identity or desktop message relay is unavailable. A phone that can say “收到” but cannot deliver the task is not ready.
- Keep one active call and one dial attempt at a time. Write the durable line guard before pressing the recent-call row, which may already create a system call. Observe that exact call concurrently from the first possible action: UI failure must not prematurely close its prepared voice bridge, and Active must not wait for a stuck confirmation read. Keep the original bounded deadline, cancel pending UI steps after resolution, and never repeat either click. An unbound failure banner cannot fail a newer Sending/Active call. Never open `.xpc`, extensions, or application bundles as call targets.
- A timeout is not a confirmed hangup. If `phone-line-unconfirmed.json` exists, retain queued completions until real CallServices disconnect is observed; never clear it simply to force a call. Mid-call voice or command-transport loss gets one pre-rendered failure notice in the selected voice, not fifteen minutes of silent fake success or an automatic redial.
- Stage reports and manual-call exemptions against the exact active root turn ID. A session-wide fifteen-minute flag cannot safely deduplicate a long task; stale turn-bound flags must never affect later turns.
- A failed native report preparation is recorded as this root turn's failed attempt, not as a user-requested skip. Do not generate a third clip or let the completion fallback retry it; later distinct turns remain enabled. If an older wrapper failed before recording it, use the installed `hook_stop.py preparation-failed --thread-id <exact source>` once after verifying the rejection, without rerunning synthesis.
- The pinned audio receiver uses a bounded packet reorder buffer. Preserve this per-peer adapter and its packet-loss/wraparound regression tests: the stock buffer was verified to discard received speech after sequence gaps. Unified native mode adds bounded Opus FEC/PLC for small, duration-consistent sequence gaps, never arbitrary timestamp jumps or global library patches. Concealment is not recovery of original missing speech, and passing ASR is still not human listening acceptance.
- Do not store OpenAI API keys. The iPhone path uses the user’s logged-in Codex account and ordinary SIM call service.
- Phone numbers and provider credentials stay in the local state directory with mode `600`; never put them in the skill, project, logs, or chat output.
- Preserve normal Codex authorization boundaries for commands received by phone. A phone request does not authorize unrelated paid, destructive, login, publication, or external-send actions.
- Do not claim success from a queued JSON file. Verify Phone.app call state for calls and verify a new/steered target turn for relayed commands.
- Keep automatic backing responses enabled for live conversation; client-managed handoffs without an explicit answer handler deadlock queries. Literal pre-rendered speech remains client-managed. Count a cached waiting notice as feedback, never as the question's answer or a latency pass. Missing query information should be clarified directly; a failed real-time lookup must not become an execution command or an invented factual answer.
- Treat `rate_limit_exceeded` as a voice-service quota failure, not an ordinary disconnect. Stop live generation tests; do not switch to API-key authentication, buy credits, use resets, or keep retrying. Ordinary Codex percentages do not establish Realtime quota or its reset time. Record this completion with `hook_stop.py preparation-failed --thread-id <source> --reason realtime_quota_exhausted` without another synthesis attempt; keep later session callbacks enabled.
- Archive queued, playing, partially cancelled, and device-output-complete states separately. Device callback completion still does not prove what a caller heard. Interrupted command receipts resume after caller silence; cancelled audio must not appear as played in test exports. Preserve the timestamp fence and all-path short-audio gate. Only the initial greeting is suppressed; later “喂、在吗” gets a normal response.
- Local caller silence can precede the recognizer's last words. Keep the longer ASR settle window after local VAD; only a correlated server-final transcript uses the short path. Every accepted late aggregate fragment restarts settling; an old aggregate completion must not close the next utterance. Classifier history ends before the current caller utterance, excluding speculative same-turn replies and suppressed acknowledgements. A model beginning or finishing an answer cannot finalize the caller's still-pending words: hold its audio until the whole utterance is classified. A slow tail must not become several separate commands/classifications. Suppress the original greeting by its utterance identity even when its model reply arrives after the opening report; do not suppress later greetings. Stopping a story or asking for a different conversational tone is not a project command unless the caller explicitly requests a persistent project/settings edit.
- Persist phone dialogue under the exact source thread in the private state directory. Archive checkpoints also write a per-call Markdown and stable `电话记录.md` view, preserving recognition uncertainty, partial/unplayed output and factual delivery states. On a received phone command or a request to see missing records, use `open_in_codex` to show that source's supplied `conversation_display` file and provide its file link; distinguish an opened panel from a queued open. Earlier dialogue remains quoted context, never new instructions. This file view is not a live chat transcript pane; do not send old dialogue as new task prompts to make it visible. Backfill instructions are in operations.
- Each uncached native clip uses a fresh read-only context and timestamped media fence, and must finish its own newly-created assistant turn. An unrelated late `turn.done` cannot complete it. Store the exact clip, phase, timing and partial media diagnostics even on cancellation, and preserve each rejected attempt's own completion events. Register its exact literal script as non-executable developer `initialItems` context at startup, then send its speakable text once through the ready authenticated V3 data channel; never also send the sideband speech RPC, retry an uncertain send, issue a startup reading command or a second live context update. Local enqueue is not server acknowledgement or completed speech. Known startup turns remain ineligible even if their callbacks arrive after the append. Keep exact script and waveform validation; never collapse repeated transcript text into success or blindly cut repeated audio. This pre-rendering change does not change live question/answer or same-session repair routing.
- Text completion and received audio completion are separate. Keep the bounded tail-drain window open until the corresponding media end has arrived; a late tail cannot be discarded just because the text finished. Missing media or a failed reader cannot become a validated cached clip. Live replies likewise cannot pass their structural check on prefix length alone when their media tail is missing. This does not fix unclear speech already present in the received signal or replace listening acceptance.
- Query deadlines belong to the original user utterance, not a global playback counter. Another receipt or waiting notice cannot mark that question answered. Archive timeout replies. Detect a started voice stream that then stalls and provide one prepared same-voice failure notice, suppressing its stale tail. A complete short answer must not be rejected solely for being under one second.
- Refresh only bounded exact-source user/final records and factual delivery receipts into the temporary voice context. Updates are background facts, not fresh execution instructions or a reason to speak. Delivery/started state is not completion; do not invent current progress if refresh fails.
- Record preparation, Phone.app confirmation, system dial, Active, and disconnect timing separately. A long cellular `Sending` interval is not Codex processing latency.
- Reject a newly separated transcript when real phone input has supplied no new acoustic utterance, including aggregate user turns without word-fragment events. Accept an aggregate turn's later completion only under the same already-verified identity. Silent pickup cannot create an executable command. Keep rejected text as diagnostic data, not caller dialogue.
- Media/data events can arrive in either order. Derive the first word from word-level output timestamps, then preserve its connected waveform onset across the boundary; do not extend through a separate old voice tail. Check actual saved speech as well as transcript strings.
- An incomplete native answer that has never been played may receive one same-session, same-voice literal repair. Keep the original question deadline, require identical words, suppress stale/cancelled repairs, and never repeat an already streamed answer or retry indefinitely. A failed repair gives one prepared failure notice and stops that question's other timers. This is not another telephone attempt.
- If a command was already sent, forward an explicit cancellation as a new uniquely identified request to the same source task; do not resend the original command or claim an undo has happened. Pending unsent commands may be cancelled locally.
- Do not put a waiting filler ahead of native audio that is already buffered while classification finishes. A greeting alone must not start a question timeout. An accepted command, a query answer, and audible device output remain separate evidence.
- Keep prepared receipt/report records separate from speculative model speech. The action classifier may suppress an unverified model acknowledgement, never the playback record of the actual delivery receipt.
- After an action, play exactly one factual fixed receipt and then wait; no query-wait filler, extra advice, architecture explanation, or invitation. For a correlated new or steered target turn that has begun processing, use the complete selected recording: “收到指令，已经发送并且开始执行，请您耐心等待，执行完成后会电话通知您。” Synchronous Stop exact-command verification has a thirty-second maximum and returns immediately when new processing is confirmed; legacy desktop confirmation retains its six-second bound. Never wait indefinitely or resend while observing. If only delivery is confirmed, say explicitly: “指令已经送达，执行状态暂未确认。” Prepare that distinct failure-status notice before deployment; do not automatically substitute a cropped suffix of the approved recording. Retain old clips as evidence. Archive the actual selected words, not the unavailable default. Never promote delivery to started merely to match preferred wording. Stop query timers as soon as an utterance is classified as an action, before waiting for delivery; unresolved intent cannot authorize a query filler. Subsequent questions still get normal answers.
- Queued reports older than 15 minutes (or with invalid age metadata) are retained for explicit review, not silently discarded or dialed much later. A newer valid completion remains eligible. Releasing one held report requires the user's explicit instruction and `confirm-queued-report --job-id ... --confirm`; that operation consumes the current turn's one call. Do not automatically release a backlog or clear an unconfirmed line guard.
- Failures have private per-job service status and at most one desktop-notification submission. Publish terminal state after durable job settlement on every provider path, including iPhone preparation/dial failures, skips and crash recovery. Never send failure alerts as source-task prompts, which could create a callback loop. OS submission does not prove the banner appeared. Phone-call completion does not prove the requested source task completed. Preserve these distinctions in status and exports.
